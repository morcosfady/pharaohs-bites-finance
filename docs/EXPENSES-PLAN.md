# Expenses rebuild: plan (started 2026-10-01)

Goal: Expenses tab = single source of truth for every business expense, tax-ready, **one real purchase counted once**.
No secrets or personal data in this file (public repo).

## Findings (before any change)

1. **"Failed to send a request to the Edge Function"**: the deployed `plaid-*` functions were from 2026-09-26 and answered the browser preflight with the old origin (`morcosfady.github.io`), not `finance.pharaohsbites.com`. Source was already right. Fix = redeploy (done, preflight verified).
2. **"Last sync: never"** and no reconnect warning ever: `bank_items` (holds the Plaid token) has no RLS policy, so the embedded `bank_items(...)` in `useBankAccounts` always came back null. Fix = column-level grant (token column stays unreadable) + admin policy.
3. Recurring subscriptions are real rows generated by `generate_due_recurring_expenses()`. A bank charge for the same subscription would create a **second** expense. The matching engine must link them.
4. Existing live data: 2 expenses (Anthropic monthly template, Court Solutions bank import), 1 Chase item, 3 bank transactions (one Zelle from owner, one deposit, one $10 charge).

## Data model (migration 0046)

- `expenses` = one row per real money event (what totals count). New: `review_status` (ok | needs_review | possible_duplicate), `duplicate_of`, `merged_into`.
- `expense_sources` = evidence. `(source_type, source_ref)` is **unique**. Types: bank, receipt, email, stripe, manual, subscription, mileage. Columns: expense_id (nullable), raw, parsed, confidence, `merged_from`.
- `expense_items` = line items (Phase 2).
- `bank_transactions.kind`: expense | transfer | owner_contribution | personal | payout | money_in | pending | ignored. Only `expense` ever becomes an expense.
- `bank_rules.action` + `direction`; `vendor_aliases` (+ `normalize_vendor()`); `expense_settings` (match window days, amount tolerance).
- Matching lives in **one SQL function** (`find_expense_match`) used by bank sync now and receipts/emails in Phase 2.
- Totals always come from `expenses` only.

## Matching score (SQL)

amount within tolerance (40) + same normalized vendor (40) + date within window (up to 20), candidate must not already have evidence of the same type.
- >= 80 high: auto-link (bank charge attaches to the manual/subscription/receipt expense).
- 40-79 medium: new expense, flagged `possible_duplicate` with `duplicate_of`; owner picks Merge or Keep both.
- two bank transactions are **never** merged with each other.
- Merge is reversible (`merge_expenses` / `unmerge_expense`), audited.
